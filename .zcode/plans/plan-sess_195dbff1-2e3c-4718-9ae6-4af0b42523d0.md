## 阶段 1：数据体逆向（核心攻坚，尽早暴露风险）

### 1a. `.lid` 点云数据体
- 以 0x6B5(CRC) 之后为数据区起点，按 DecodeTool 字段表 + `logLidarDecode.txt` 线索（276000B/包、m_nFramePackNum=200、每帧 ~12000 点、帧时间跨度 ~0.096s）扫描帧结构：找帧头同步字、点数（~12000=0x2EE0）、时间戳（GPS 周内秒 176551.x 附近的双精度或整数）。
- 确定单点记录布局（假设 int16 XYZ + intensity/回波，参考 DecodeTool 遗留输出格式 `x y z intensity + short`），用 Python 验证：
  - 静止段（开头几秒）点云半径分布应在厘米级~30m 合理范围
  - 点数 × 记录长 + 帧头 = 包长整数倍
  - 与 logLidarParse.txt 的逐帧时间戳（176551.484→…）逐帧对齐
- 产物：`decode_lid.py`，输出逐帧 `npy/pcd`（xyz + intensity + 帧时间；帧内 offset_time 线性插值 0~96ms，ring=0）。

### 1b. `.dat` KQI 容器中的 IMU
- 解析 `KQI\0 + u16类型 + u16载荷长` 记录流；69B 记录（60B 载荷）疑似 200Hz IMU：试解 float32 ×（gyr3+acc3+温度/计数），按 IMUAxis(-Y,+X,+Z) 重映射轴向。
- 验证：静止段 |acc|≈9.8 m/s²、采样间隔 5ms、与 logZUPT 时间轴一致（176546.278 起）。
- 产物：`decode_dat.py` → `imu.csv`（t, gx…az）。
- 若 IMU 原始记录无法解出：fallback 为向公司索取 .imu 独立文件格式说明。

### 1c. 汇报检查点
阶段 1 结束输出：点云可视化截图（open3d/CloudCompare）、IMU 曲线、静止段统计。**任一失败则停下汇报**。

## 阶段 2：生成 rosbag（Windows 本机，纯 Python `rosbags` 库，无需 ROS）

- 时间统一：GPS 周内秒 → Unix epoch（GPS 周约 2432，含 -18s 闰秒），三传感器共用；跨 3 个 .lid 文件按 No000/001/002 顺序拼接。
- 话题与消息：
  - `/livox/lidar`：PointCloud2，字段 x,y,z,intensity,time(float,帧内秒),ring（lidar_type=2 路径）
  - `/camera/image_raw`：M 相机 3327 张 JPG → sensor_msgs/Image(bgr8)，文件名 GPS 时间戳
  - `/imu/data`：sensor_msgs/Imu + 典型协方差
- 验证：`rosbags` 读回检查消息数（雷达~3007、图像3327、IMU~58750）、时间单调、频率。

## 阶段 3：FAST-LIVO2 配置（标定换算，全部来自文件头实测值）

- `config/camera_project10.yaml`：M 相机 fx=fy=4.1618mm/2.4μm≈1734.1，cx≈640±31.7px、cy≈540∓19.3px（主点偏移符号在阶段 1 用实际图像光心验证），畸变 K1:0.0812, K2:-0.0069, K3:-1.484（K3 异常大，需核对 DecodeTool 的 K/P 字段定义与新版 f8K/f8P 排列后再定 d0-d3）。
- `config/project10.yaml`（基于 avia.yaml）：
  - `extrinsic_T/R`（LiDAR→IMU）：L2M 单位阵 + 中心偏移 (0.023,-0.011,0.044) 与 M2I 的 Z 轴 -90° 旋转链合成
  - `Rcl/Pcl`（LiDAR→M 相机）：由 Camera2B1 (-2.685,-71.275,92.764)° + 杆臂 (0.0345,0.0066,-0.0932)m 与 LiDAR→B1 链合成（角度序/旋转序按 DecodeTool 字段说明与实际场景验证，先给初值再微调）
  - `scan_line:1`、`blind`、IMU 噪声按 ICM40609 手册、`img_time_offset` 用 i4XRayDelay 0.001s
- 新建 `launch/mapping_project10.launch`。
